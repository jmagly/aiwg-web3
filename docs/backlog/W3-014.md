# [W3-014] Evaluate generalized capabilities in independent consumer projects

## Objective

Presence of a generic prompt is insufficient evidence that it works beyond its source project.

## Scope

Define capability-specific rubrics and fixed tasks, record baseline versus generalized results, and evaluate a second EVM project plus a non-Web3 graphics consumer when that addon ships. Test interruption, missing context and adverse tool results.

## Acceptance criteria

- [ ] Per-module rubric and fixtures are versioned
- [ ] Evaluation checks correctness, authority boundaries, recovery and evidence quality
- [ ] No embedded Roko assumptions survive fixture substitution
- [ ] Failures have linked issues; release excludes unverified modules
- [ ] Reproduction commands, dependency versions and observed outputs committed
- [ ] Readiness decision reviewed against W3-001 release scope

## Dependencies and priority

Priority: P0 release blocker. Depends on: W3-002, W3-005, W3-006; optional module evaluations depend on their implementation.

## Completion evidence

Link implementation commits, fixture/test commands and observed results, updated docs, and any residual limitations. A prompt file or successful archive build alone is not proof of capability readiness.
